# 圆形绿光识别验证记录

验证日期：2026-10-02

## 范围

本次验证相机、圆形绿光检测、MCU IMU 接收和估计配对链路；没有启动任何执行机构输出。
`ros_sp` 仅作为经过验证的只读迁移来源和 Docker 环境来源，代码、配置和构建产物均写入
DART 仓库自己的 `ros2_ws`。

## 实机 MCU 与估计链路

在 Docker 容器中确认 `/dev/ttyACM0` 已映射后，使用 `dart_bringup` 同时启动
`camera_node`、`detect_node`、`mcu_node`、`estimate_node`。实测结果如下：

| 项目 | 结果 |
| --- | --- |
| 串口 | `/dev/ttyACM0`，115200 8N1 |
| MCU RX 发布频率 | 约 1000 Hz |
| 样本序号 | 连续增长（实测 `6514`） |
| 四元数 | 成功解码，例如 `(w,x,y,z)=(0.9769,0.0188,0.0589,-0.1962)` |
| 估计节点 `imu_valid` | `true` |
| IMU 配对年龄 | 约 5.8 ms |
| 现场无绿灯时估计 | `target_detected=false`、`valid=false`，符合现场 |

`mcu_node` 原样转发协议中的姿态、角速度、加速度和四元数字段；`estimate_node` 明确以
`imu_units_verified=false` 标示尚未在本仓库定义单位/轴向，避免在未确认协议语义前错误换算。

## 合成端到端验证

通过 ROS topic 发布半径 30 px、每帧向右 2 px、向下 1 px 的绿色圆，并发布
`fx=fy=500 px` 的 CameraInfo。检测节点的代表性输出：

| 输出 | 实测值 |
| --- | --- |
| 圆心 | `(252.0, 196.0) px` |
| 半径 | `30.0001 px` |
| 帧间像素变化 | `(2.0, 1.0) px` |
| `delta_valid` | `true` |
| 水平/竖直偏转角 | `(-0.135171, 0.087774) rad` |
| 帧间角度变化 | `(0.003925, -0.001984) rad` |
| 圆度 | `0.8915` |
| 填充率 | `0.9655` |
| 单帧处理时间 | `1.19 ms` |

圆心、半径和固定步长均符合生成值。角度使用畸变校正后的归一化坐标计算；竖直角以图像
上方为正。

## 实物绿灯复测

把实际圆形绿灯放入视野后执行：

```bash
ros2 topic echo /detect_node/detection
ros2 run rqt_image_view rqt_image_view /detect_node/debug_image
```

重点检查不同距离与曝光下的圆度、半径稳定性和背景误检，再调整
`config/standard3.yaml` 中的 HSV、面积、圆度及填充率阈值。不要以降低阈值制造正检；
应保留当前无目标时的稳定负检能力。

## 已知边界

- 多个合格圆同时出现时，当前选择综合得分最高的候选。
- 目标丢失后会清除历史；重新捕获的第一帧 `delta_valid=false`。
- CameraInfo 未到达时暂用 standard3 内参；收到 CameraInfo 后自动切换并应用畸变参数。
- 半径是原始图像像素半径，角度则使用去畸变后的圆心计算。
